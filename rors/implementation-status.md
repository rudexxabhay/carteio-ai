## Current limitations

The runner executes saved Chat Input, one or more Carteio Assistant nodes, If / Else condition nodes, Knowledge Search nodes, Message Template nodes, and one or more AI Response leaves. Assistant nodes can select workspace assistants and pass replies forward. Conditions compare the current value with a configured string using case-insensitive contains, equals, or starts-with matching. The editor exposes ordered True and False ports. Each branch must reach its own response and include an assistant; branch merges and cycles are rejected. The selected branch runs and unselected nodes are skipped, with skipped node IDs included in run results and shown in the test panel. Knowledge Search nodes call the existing authenticated manager preview with assistant scoped connector and source permissions; results, scores, source titles, retrieval mode, and eligible source count are returned in `knowledgeRuns` and shown in the run panel. They expose retrieval evidence as trace output and do not inject retrieved text into an assistant prompt. The API records assistant outputs in `assistantRuns`, combines returned knowledge sources, records the chosen branch in step metadata, and uses deterministic per-node turn IDs for replay-safe repeated runs. Templates substitute `{{input}}` and enforce existing assistant message bounds. A post-assistant template changes the flow's `reply`; `assistantReply` preserves the last raw assistant output, and each stored conversation transcript remains that assistant's raw response. Flow saves use optimistic version checks and reject stale editor writes with a conflict. The editor marks conflicts separately from network outages, preserves the local draft, and offers an explicit load-latest action to recover the server version without discarding that browser copy. Assistant nodes delegate provider selection, knowledge retrieval, conversation persistence, and response safety to Carteio's existing orchestration. The Knowledge Search node is a retrieval trace step; a standalone retriever whose output is passed into another model prompt is not available. Independent model, tool, loop, human approval, subflow, and HTTP nodes are not available yet. Run traces are returned for the request but are not retained as history; provider calls return complete responses rather than token streams. The manager-only persistence and run endpoints use the additive schema, which remains pending migration approval.

No migrations were run. The existing assistant, auth, knowledge, crawler, provider, connector, Shopify, widget, commerce, and conversation systems remain in place.

## Knowledge Search integration

Flow graphs accept an optional `knowledgeLimit` from 1 to 10 (default 5). Each Knowledge Search node can select its own assistant, falling back to the flow-level assistant. During a run the node queries that configured assistant, through `KnowledgeProcessingService.searchPreview` with `INTERNAL_MANAGER_PREVIEW`. This reuses the service's workspace membership, active-assistant, effective source assignment, connector permission, and index readiness checks. The result is included in the run response and rendered in the trace. It does not change the message passed to the next node, and retrieved content is not placed into model prompts. This makes the node useful for inspecting retrieval behavior while preserving the assistant orchestrator's established context and safety handling.
